# 記事の品質チェックリスト（統合版）

作成: 2026-11-19（代表が提示した「AI記事の品質チェックリスト【統合版】」を標準として固定）。
対象: `src/content/crm-media/{ja,en}/` の記事。運用の手順は `daily-run.md` の工程7、記録の例は `reviews/` を見る。

目的は「AIっぽさ」を消すことではない。専門性・信頼性・読みやすさを備え、公開に耐える記事にすること。以下の6領域で管理する。

## 1. ファクトチェック（最重要）

- 数値・統計・割合・金額・件数に、信頼できる出典がある。
- 可能な限り、公式サイト・公的機関・原著論文などの一次情報を参照している。このメディアでは、crm リポジトリの実装と公開ページが一次情報。
- 企業名・サービス名・人名・役職名が正確。
- 日付・年号・時系列に矛盾がない。
- 法律・制度・料金・サービス仕様が、執筆時点で最新。
- 引用が原典と一致し、URLが実在して正しいページに遷移する。
- 「業界No.1」「多くの企業が導入」などの表現に根拠がある。
- 専門的な説明に、事実誤認や不正確な解釈がない。
- 架空の事例・人物・調査結果・実績を生成していない。
- 事実・推測・筆者の意見を区別し、出典不明の情報を断定していない。
- 根拠を確認できない事実は、「修正」「削除」「要確認」のいずれかに分類する。

## 2. 構成・論理（高）

- タイトルと本文が一致し、冒頭で読者の疑問・課題への答えを示している。
- 読者が知りたい情報を優先し、見出しの順に論理的なつながりがある。
- 各章の役割が明確で、重複がない。重要な章は十分に説明している。
- 章の長さを不自然に均等にしていない。すべての章を同じ「概要→3ポイント→まとめ」にしていない。
- 主張と根拠のあいだに飛躍がない。原因と結果、相関と因果を混同していない。
- 不要な前置き・一般論・脱線で文字数を増やしていない。
- まとめが本文の単なる繰り返しになっていない。
- 各章について「この章がなければ読者は何に困るか」を説明できる。

## 3. 内容の具体性・専門性・独自性（高）

- 「さまざまな」「多くの」「一定の効果」などの曖昧語を、必要以上に使っていない。
- 抽象的な説明に、理解を助ける具体例・実数・固有名詞が伴っている。ただし数字は創作しない。
- 一般論だけでなく、専門的な知見や実務上の示唆がある。
- 筆者独自の視点・経験・観察・分析、またはこの記事ならではの情報がある。
- 架空の例を実話として扱っていない。例は主張の理解に役立っている。
- 必要なデメリット・制約・適用条件を説明している。
- 読者の知識水準に合い、「なぜそう言えるか」が分かる。
- 実務の判断基準や具体的な手順がある。
- 筆者名を外しても成立する、一般論だけの記事になっていない。

## 4. 日本語表現（中）

英語版は、下の各項目を自然な英語の基準に置き換えて確認する（翻訳調、同じ構文の反復、根拠のない誇張、定型の締め、不要な前置きなど）。あわせて、日本語版との事実の差と、英語圏の読者への適合を見る。

### 4-1. AI特有の表現

- 「〜ではないでしょうか」「〜と言えるでしょう」を多用していない。
- 「いかがでしたか」「ぜひ参考にしてください」などの定型の締めがない。
- 「近年」「昨今」「現代社会において」など、不要な導入がない。
- 「また」「さらに」「加えて」を連続して使っていない。「重要です」「大切です」「ポイントです」を繰り返していない。
- 不必要な丁寧さや、過剰な共感がない。
- 「革新的」「画期的」「非常に有効」など、根拠のない誇張がない。
- 翻訳調の不自然な日本語や、同じ言い回し・文型の反復がない。

### 4-2. 読みやすさ

- 同じ語尾が3回以上連続していない。
- 一文が必要以上に長くない（60〜80字を目安に確認する）。
- 一文に複数の主張を詰め込んでいない。主語と述語の対応、指示語の対象が明確。
- 「〜することができます」などの冗長な言い方を簡潔にしている。同じ意味の文を繰り返していない。
- 不自然な体言止めや疑問形を多用していない。
- 一文ごとの機械的な改行を避け、意味のまとまりで段落を作っている。
- 箇条書きは必要な場所に限っている。

### 4-3. 表記・校正

- 誤字脱字・変換ミスがない。敬体と常体、表記、数字、単位、記号を統一している。
- 固有名詞の大文字・小文字が正しい。
- 専門用語・カタカナ語が読者に適している。
- 二重表現・重複表現がない。句読点・括弧・引用符を統一している。
- AIらしさを消すために文章を崩していない。意味が正確に伝わる自然な日本語にする。

## 5. 読者体験（高）

- 対象読者が明確で、その疑問・課題に答えている。
- 冒頭で記事の価値が伝わる。
- 冗長さによる離脱要因や、説明不足がない。必要な専門用語は説明している。
- 具体例や比較が理解を助けている。
- 見出しだけで要点を把握でき、情報を探しやすい。
- 読後の判断・実行が明確で、目的に合った自然な導線がある。
- 読者が「何が分かったか」「どう判断するか」「次に何をするか」を説明できる。

## 6. 公開前確認（最重要）

- タイトル・見出し・本文に矛盾がなく、数値・日付・固有名詞・URLを確認済み。
- 未確認情報や仮置きが残っていない。
- 引用・転載が適切で、著作権上の問題がない。必要な出典・参考資料を明記している。
- 画像・図表が本文と一致している。
- 筆者の意図にない主張や、事実・体験・実績の創作がない。
- 全体で同じ主張・説明が重複していない。
- 筆者の見解・文体・専門性を反映している。

## 3段階の運用

| 工程 | 対象 | AIの役割 | 人間の役割 |
|---|---|---|---|
| ①事実検証 | 1・6 | 検証対象の抽出、一次情報との照合 | 出典・事実の最終確認 |
| ②編集レビュー | 2・3・5 | 構成・論理・独自性・読者体験の評価 | 主張・構成の修正判断 |
| ③校正・推敲 | 4・6 | 日本語・重複・表記ゆれの修正案 | 文体と意図の最終確認 |

工程は①→②→③の順に行う。校正と編集は別の工程で、誤字を直しても論理や情報の価値は上がらない。

### 共通ルール

1. 指摘と修正を分ける。最初は、問題箇所・理由・修正案だけを出す。
2. 原文を必ず短く引用し、場所を特定する。
3. 重大度は3段階で付ける。
   - Critical（公開不可）: 事実の誤り、根拠のない断定、創作、禁止事項への違反など、外れたら読者と筆者の信用を損なうもの。
   - Major（修正推奨）: 読者が誤って理解・操作する恐れ、論理の飛躍、主要な説明不足。
   - Minor（改善任意）: 表記ゆれ、言い回し、読みやすさ。
4. 問題がない項目は「問題なし」と書く。無理に指摘を作らない。
5. 根拠なく補完しない。確認できないものは「要確認」と書く。「要確認」は「問題なし」ではない。
6. 筆者の主張・文体を勝手に変えない。修正は承認の後に行う。

### 評価と蓄積

| 指標 | 基準 |
|---|---|
| 事実の正確性 | Critical 0件 |
| 論理・構成 | Major 0件 |
| 独自性 | 筆者固有の知見が1つ以上 |
| 日本語品質 | 誤字脱字・不自然な表現なし |
| 読者価値 | 疑問に答え、判断材料を提供している |
| 公開判定 | 未解決の Critical・Major が0件 |

件数の基準は暫定。Minor まで0にする必要はない。各記事の「指摘箇所・重大度・修正案・対応状況」を蓄積する。

### 解釈上の重要事項

- 具体性と正確性は別。根拠なく「継続依頼3〜5本の直後」のような数字を作らない。
- 「ではないでしょうか」「また」そのものを一律に禁止しない。不適切な多用を評価する。
- 独自性は実体験だけで評価しない。複数の一次情報の比較・分析、独自のフレームワーク、新しい理解や判断材料にも価値がある。体験の捏造は不可。
- 校正と編集は別の工程。誤字を直しても、論理や情報の価値は改善しない。

## 公開判定と、原稿を直す条件

- 公開してよいのは、未解決の Critical・Major が0件の記事だけ。「要確認」が残る事実は、確認できるまで本文で断定しない（言い方を弱める・削る・確認する、のどれかを記録する）。
- 修正は承認後に行う。例外は置かない。未公開・公開済み、重大度、修正の種類（事実の訂正・表記・禁止表現を含む）を問わず、まず指摘と修正案を出し、代表（山口）の明示の承認を得てから原稿に反映する。
- レビュー担当は、指摘と修正案を出すところまでを行う。原稿は書き換えない。
- 新規原稿の作成と、レビューの指摘を受けた修正は別物。レビュー後の原稿の変更は、すべて承認の対象になる。日次の公開での扱いは `daily-run.md` の工程7に書く。

## 記録先

- 記事ごとのレビュー結果: `docs/crm-media/reviews/<公開日>-<内容>.md`
- 日次の実行記録: `docs/crm-media/runs/<日付>.md`（レビュー結果のファイル名を書く）
- 1件ごとに残す項目: 記事（slug・言語）／工程（①②③）／原文の短い引用／問題箇所／理由／根拠（ファイルと行、URL、確認日）／重大度／修正案／対応状況（未対応・承認待ち・対応済み・見送り）／要承認事項／記事ごとの公開判定
