# 1. コンセプト

## 芯にある一文

> **止まっているのは、努力が足りないからではない。顧客データがつながっていないから。**
> **つなぎ直して、動くところまで伴走する。**

「止まる → つなぐ → 動く」。この動詞の流れが、サイト全体の骨格になる。

**重要**：「止まる」だけでは機能しない。**「止まる」で始めたら「動く」で終える**。
問題を積み上げて手段を語り、その先の絵を見せずに終わる構成は、
「うちの何が壊れているか教えてくれる会社」で着地してしまう。

## 5層構造

| 層 | 内容 | 役割 |
|---|---|---|
| 症状 | 「顧客情報がまだExcelとメールにしかない」「入れたSFAに入力されない」「施策の成果が売上として見えない」 | 訪問者の自己認識をつくる |
| 診断 | 原因は努力ではなく、マーケ・営業・CSでバラバラになった顧客データという構造 | **最大の差別化。読み手の責任を解除する** |
| 解決 | つなぐ → 見えるようにする → 回るようにする | 何をするのか |
| After | 動き出したあとの姿 | 約束を回収する |
| 旗 | レベニューアーキテクチャ／RevOps | カテゴリを取る |

受け皿は**収益診断**。約束の動詞は**「事業を、前に進める」**。

## 2つの事業を「はしご」として見せる

Consilegy にはコンサルティングと自社プロダクト Revenue CRM（コンセプト＝「企業の最初のCRM」）がある。
ICPが異なるため、規模で切ると片方の顧客を弾く。**段階で切ってはしごにする。**

```
1段目  まだCRMがない。顧客情報がExcelとメールにしかない     → Revenue CRM
2段目  CRMは入れた。でも入力されない、数字が信用できない     → コンサルティング
3段目  設計はある。回し続け、伸ばしたい                       → 伴走・顧問
```

はしごにすると3つ得がある。

1. **同じ一文で両方を説明できる** — CRM未導入＝仕組みが未設計、CRM機能不全＝設計を間違えた。どちらも「設計の問題」
2. **ベンダーフリーとの矛盾が消える** — 1段目の顧客には既存ツールが無いので、中立性の対象がそもそも存在しない
3. **1段目の顧客が数年後に2段目の顧客になる** — 自前のパイプラインになる

# 2. 4つの戦略判断とその根拠

## 判断1：規模ではなく「段階」で切る

**根拠A：競合20社超で、企業規模を名指ししている会社はゼロだった。**

調査対象（才流、ベイジ、セレブリックス、Sales Marker、Mazrica、openpage、Magic Moment、ブリッジインターナショナル、サンブリッジ、イノーバ、THE MOLTS、Faber Company、WACUL、100（ハンドレッド）、リベラルハーツ、セラクCCC、パーソルBD、Xactly、NIコンサルティング、ソフトブレーン、SATORI、List Finder、GENIEE、ferret One、LEAPT、メディックス、リブ・コンサルティング、船井総研、SEデザイン、リードプラス ほか）。

大企業向け（エンタープライズ／ガバナンス訴求）と中小向け（安さ／簡単さ）の二極は明確に存在するが、
「中堅企業」「従業員◯名〜◯名」と名指しした会社は1社もなかった。HubSpot Japanですら二分で中間層への言及がない。

**根拠B：ただし入口で規模を書くと、Revenue CRM の顧客を弾く。**

「従業員50〜300名に絞って」と書くと、20名の会社は自分を対象外と判断して離脱する。
その20名の会社こそ「企業の最初のCRM」の本命顧客。

**結論**：入口では段階で切る。規模（50〜300名）は**料金セクションに移す**。
ここまで読む人はすでに自分がコンサル側だと判定済みなので、規模の記載が排除にならない。

### Revenue CRM の対象を「CRM未導入」1つに絞る理由

| 動機 | 競合になるもの | 採否 | 理由 |
|---|---|---|---|
| まだCRMがない | Excel・スプレッドシート・紙 | **採用** | 機能比較が起きない。移行作業がない。ベンダーフリーと矛盾しない |
| 今のCRMが使いにくい | Salesforce・HubSpot | 不採用 | 「既存ツールを前提に設計する」というコンサルの中立性と正面衝突する |
| 料金を下げたい | GENIEE（6,300社）、ソフトブレーン（6,000社）、List Finder（月45,000円〜／フリープラン0円）、Mazrica（月6,500円/ID〜） | 不採用 | 規模で価格を作れる相手に価格で勝てない。かつ価格で来た顧客は次に安いものへ移る |

**市場規模の裏づけ**：日本企業のCRM導入率は37.2%（HubSpot Japan「日本の営業に関する意識・実態調査2025」）。
6割以上がまだ持っていない。

**定義は規模ではなく状態で書く。**「まだCRMを持っていない会社の、最初の1つ。」
訪問者は従業員数レンジの判定には迷うが、「CRMがあるか無いか」の判定には迷わない。

## 判断2：価格をファーストビュー近くに出す

**根拠：日本のB2B購買者が最も信頼する情報の1位は「価格・追加費用・契約条件が明瞭であること」で60.6%。**

（HubSpot Japan×マクロミル「日本のBtoB購買に関する意識・実態調査2026」2026年6月11〜16日、n=1,573、
直近12ヶ月にBtoB商材の比較・選定・稟議等に関与した従業員50名以上企業の勤務者。一次情報で確認済み）

同調査より:
- Webサイトで確認したい情報の1位も「価格や費用の目安がわかる」42.9%
- 売り手との最初の接点の目的の1位が「価格・見積もりを確認するため」42.4%

他の調査でも:
- 問い合わせ判断で最も重視されるコンテンツは「料金・費用情報」25.7%（Cone調査 n=221、2025年10月）
- サイト上で参考にした情報の2位が「価格/料金表」65.0%（ITコミュニケーションズ／B2Bマーケティング n=157、2019年）

**そして競合はほぼ出していない。** 調査18社のうち価格開示は Mazrica と WACUL の2社のみ。
コンサル・伴走型支援会社は全社が「お問い合わせください」型。

Consilegy はすでに `/pricing/` に3段階の価格を出している。
**買い手が最も欲しがっていて、競合がほぼ出していないものを、すでに持っているのに隠している状態。**

## 判断3：買い手の言葉で書く。専門用語はあとから出す

**根拠A：専門用語はコンバージョンを下げる。**

Unbounce Conversion Benchmark Report（LP 41,000件超・訪問4.64億超の分析、海外）では、
SaaS業界のLPで平易な文章（5〜7年生レベル）のCVRは12.9%、専門的文章は2.1%。**約6倍の差**。
読解レベルが1段階上がるごとに約49%減。

**根拠B：買い手は「分断」「サイロ化」「RevOps」とは言わない。**

Yahoo!知恵袋・note・導入事例の「導入前の課題」欄から収集した買い手の生の言葉:

- 「入力がめんどくさくて本当に辛いです」（Yahoo!知恵袋・質問者本人）
- 「上司から尻を叩かれないと誰も積極的には入力しません」（同・回答者本人）
- 「導入したけど、結局Excelで管理してる」
- 「手帳やExcelに依存し、顧客・案件情報が個々人・部門で分断」（プロテリアル事例）
- 「勘と経験の営業から脱却できず」（同）
- 「入力しても活用されない悪循環」（同）
- 「数字が古くて意思決定に使えない」「CRMの数字を信用できないから、結局口頭で確認する」

一方、「RevOps」「サイロ化」「リードナーチャリング」「収益プロセス設計」を
買い手自身が使っている証拠は**ひとつも見つからなかった**。すべて支援会社側のオウンドメディアでのみ確認された語。

**結論**：ヒーローは買い手の言葉（Excel、入力されない、バラバラ）で書く。
「レベニューアーキテクチャ」「RevOps」は共感が成立したあと、下部で旗として掲げる。

## 判断4：「止まる」で始めたら「動く」で終える

芯にある動詞は「止まる → 動く」の対。片方だけでは機能しない。

構成の配分を数えて確認する。

| | 問題のある配分 | 正しい配分 |
|---|---|---|
| Before（止まっている） | 4セクション | 4セクション |
| Bridge（何をするか） | 2セクション | 2セクション |
| **After（動き出した姿）** | **0セクション** | **1セクション ＋ ヒーローとCTAの締め** |

会社ページのタグラインが「事業を前に進める」である以上、
サイトも同じ動詞で着地させないと、LinkedIn → サイトの導線でメッセージが切れる。

**実績数値の扱いもこれに従う。** 65%削減・月100時間・20%向上は、
数字として並べるのではなく、**その数字が意味する日常の変化とセットで置く**。
CXLの社会的証明研究（アイトラッキング＋事後調査、海外）では
「写真は記憶に残るが、ロゴと数字は記憶に残らない（photos are memorable, logos and numbers are not）」
という結果が出ている。数字単体は記憶されない。

# 3. トップページ コピー本体

## セクション1｜ヒーロー

```
売上が止まっているのは、営業力の問題ではありません。

「顧客情報が、まだExcelとメールにしかない」
「入れたはずのSFAに、入力されない」
「施策の成果が、売上として見えない」

これから仕組みをつくる会社も、つくったのに動いていない会社も、
原因は同じところにあります。顧客データが、部門ごとにバラバラなこと。

Consilegyは、B2B企業の収益の仕組みを設計し、
止まっていたものが動き出すところまで伴走します。

事業を、前に進める。

支援実績40社

[ 3分の収益診断を受ける（無料） ]  [ 料金とサービス資料を見る ]
```

### 設計意図

**H1「売上が止まっているのは、営業力の問題ではありません。」**

- 「原因の否定」から入る。読者が自分（または自社の営業）を責めている状態を先に解除しないと、次が読まれない
- 「止まる」を使う競合は調査18社中**ゼロ**（「分断」がブリッジインターナショナル1社のみ、それもH1ではない）。語彙として完全に空いている

**3つの症状＝はしごの段そのもの**

| 症状 | 該当する段 | 行き先 |
|---|---|---|
| 「顧客情報が、まだExcelとメールにしかない」 | 1段目：まだ無い | Revenue CRM |
| 「入れたはずのSFAに、入力されない」 | 2段目：入れたが動かない | コンサルティング |
| 「施策の成果が、売上として見えない」 | 共通 | 収益診断 |

症状リストがセグメンテーションを兼ねる。20名の会社も300名の会社も1行目か2行目で止まる。**規模で弾かない。**

**価格をヒーローから外した理由**

はしご構成では段によって価格帯が2桁違う（Revenue CRMは月額サブスク、コンサルは300万円〜）。
ヒーローに片方の価格だけ出すと、もう片方の訪問者に誤った印象を与える。
価格は分岐セクション直後で段ごとに提示する。ファーストビュー直下には必ず置く。

### 代替案（A/Bテスト用）

**B案｜統計から入る**

```
「営業とマーケが、よく連携できている」
そう言い切れる会社は、13.9%しかありません。

残りの86.1%で起きているのは、能力の問題ではなく、
顧客データがマーケ・営業・CSでバラバラになっているという構造の問題です。

出典：Sansan「BtoBマーケティングと営業の連携に関する実態調査」2023年（n=1,000）
```

数字＋出典から入る型。GEO研究（KDD 2024）では統計・引用・出典を含むコンテンツが
生成AI検索での可視性を最大40%向上させると報告されており、AI検索に拾われる確率が上がる。
ただし「他人の話」から始まるため、自分ごと化はA案より遅い。

**C案｜自社の最強の一文から入る**

```
営業は、意味のないシステムには入力しません。
これは意識の問題ではなく、合理的な判断です。
```

自社記事（`/insights/why-crm-adoption-fails/`）にある一文。サイト全体で最も鋭い。
弱点：CRM定着に話題が寄りすぎ、売上の話に見えない。→ **診断セクションの見出しに使う。**

## セクション2｜分岐（はしご）

```
あなたの会社は、どちらですか。


── まだ、仕組みがない

顧客情報はExcelとメール、案件の状況は担当者の頭の中。
売上は伸びているけれど、誰が何を持っているかは共有されていない。

日本企業のCRM導入率は37.2%。6割以上が、まだ持っていません。
（HubSpot Japan「日本の営業に関する意識・実態調査2025」）

そこで私たちは、企業の最初のCRMをつくりました。

Revenue CRM は、まだCRMを持っていない会社の、最初の1つです。
既存システムからの移行作業はありません。今の進め方を捨てる必要もありません。
Excelでやっていたことが、そのまま記録として残るところから始めます。

[ Revenue CRM を見る → ]


── 入れたのに、動いていない

Salesforce、HubSpot、kintone、Marketo。入っているのに、営業は入力しない。
ダッシュボードの数字は信用されず、結局スプレッドシートで会議をしている。

これはツールの問題ではなく、設計の問題です。
Consilegyは、既存のツール構成を前提に収益プロセスを設計し直し、
現場が使い続けるところまで伴走します。乗り換えありきではありません。

[ 支援サービスと料金を見る → ]


どちらか分からない場合は、3分の収益診断からどうぞ。
どこで止まっているかを整理してお返しします。

[ 3分の収益診断を受ける（無料） ]
```

### 設計意図

- **「あなたの会社は、どちらですか」** — 訪問者に自己判定させる。B2B購買者の63.5%は接触前に候補を絞っており、サイトは「問い合わせを取る場所」ではなく「候補に残る場所」。5秒で行き先が分かることが最優先
- **「既存システムからの移行作業はありません」** — 未導入層にとって最大の心理的障壁は移行コスト。無いことを明示するのがこの層への最強の一言
- **CRM導入率37.2%を出す** — 「今さらCRMも入れていないと言いにくい」という恥の感情を先に解除する。多数派だと伝える
- **診断を第3の道として下に置く** — 自己判定できない訪問者の受け皿。ここを取りこぼさないことが、はしご構成の完成条件

### 書いてはいけないこと

`〜30名向け` のような規模表記。Excelで回している200名の企業を弾く。
**「今のCRMが使いにくい方へ」「もっと安く」も書かない。** 前者はコンサルの中立性と衝突し、後者は消耗戦になる。

## セクション3｜診断（原因の説明）

```
CRMが機能しない理由は、ツールではなく設計にあります。

営業は、意味のないシステムには入力しません。
これは意識の問題ではなく、合理的な判断です。

ある会社のCRMには、商談ステージが79段階ありました。
実際に使われていたのは、5段階でした。

部門ごとに最適化されたツールとプロセスは、つなぐ人がいないまま増えていきます。
マーケはMAに、営業はSFAに、CSは別のツールに顧客を持つ。
同じ会社の同じ顧客なのに、システムの中では別人として扱われている。

結果として起きるのは、この3つです。

・施策の効果が測れない —— どの施策の何円が、どの受注になったのかがつながらない
・商談が、止まった理由がわからないまま消える —— 稟議で止まったのか、価格で負けたのかが記録に残らない
・入れたツールが使われなくなる —— 入力しても返ってくるものがないから、現場は合理的に離脱する

これは営業部だけ、マーケ部だけを改善しても直りません。
単体の部門では直せない、構造の問題です。
```

### 設計意図

- 見出しは現行サイトのまま。最も価値のある一文なので触らない
- **「79段階／実際は5段階」は自社記事にある実話。サイト全体で最も強いディテールなのに奥に埋もれている。** トップに引き上げるべき最大の未使用資産
- 3つの結果は、それぞれヒーローの3症状と対応させている
- 「入力しても返ってくるものがないから、現場は合理的に離脱する」— 現場を責めない。決裁者は営業責任者であることが多く、部下を責める文章は読まれない

---

## セクション4｜解決（何をするか）

```
やることは3つです。

01 つなぐ
マーケ・営業・CSに散らばった顧客データを、CRMを軸にひとつに統合します。
Salesforce、HubSpot、kintone、Marketo、Zoho、ServiceNow——
今お使いのツールを前提に設計します。乗り換えありきではありません。

02 見えるようにする
部門ごとにバラバラだった数字の定義を揃え、経営判断に使えるダッシュボードに落とします。
「この数字は何を指しているのか」を、全員が同じように答えられる状態をつくります。

03 回るようにする
営業会議と1on1の運用に組み込み、現場が使い続ける状態まで持っていきます。
「ちゃんと入力してください」と言い続ける必要がなくなったとき、CRMは初めて機能しています。
```

### 設計意図

- 現行の3特徴（ベンダーフリー／プロセス設計から実装・定着まで／複数ツール横断の統合設計）はすべて名詞。何が起きるのか伝わらない。**動詞に変える**
- 「ちゃんと入力してください」と言い続ける必要がなくなったとき——は自社記事の一文。ゴール状態を1行で描く力が強い
- ベンダーフリーは独立した主張にせず01に埋め込む。競合の「ベンダーフリー」訴求は珍しくないため単体では差別化にならない
- **3ステップは「つなぐ→見える→回る」で、まだ動き出していない。** 直後にAfterセクションを置いて初めて「前に進める」が完成する

## セクション5｜動き出したあと（After）

```
仕組みが動き出すと、こう変わります。


営業会議が、報告会から意思決定の場に変わる

「誰がいくら」の読み上げに使っていた時間が消え、
「この案件はなぜ止まっているのか」を話す時間になります。


「あの件、どうなった？」を聞かなくてよくなる

聞かないと分からない状態が、見れば分かる状態になります。
担当者が休んでも、異動しても、案件は前に進み続けます。


数字をつくる時間が、返ってくる

ある医療テック企業（約150名）では、データ管理・抽出の作業が約65%減り、
月に約100時間が戻ってきました。その時間は、戦略に使われています。


打ち手が、当たったかどうか分かるようになる

あるITバックオフィスSaaS（約200名）では、
マーケが渡したリードのうち商談になる割合が最大20%上がりました。
「なぜ商談にならないのか」が、感想ではなくデータで話せるようになったからです。


人が増えなくても、事業は伸ばせる

3名の兼務チームで新規プロダクトを立ち上げた会社では、
2ヶ月でGTM戦略を明文化し、3名のままで回り続ける収益エンジンができました。


止まっていたものが、動き出す。
そこまでを、Consilegyの仕事とします。
```

### 設計意図

- **実績数値を「統計」ではなく「動き」として書く。** 数字の前に、その数字が意味する日常の変化を置くことで記憶される
- **最初の2項目に数字を入れていないのは意図的。** 営業会議と「あの件どうなった？」は全員に共通する日常であり、数字よりも情景のほうが自分ごとになる
- **「人が増えなくても、事業は伸ばせる」** — 中堅企業の経営課題1位は「人材強化」96.6%（帝国データバンク 2026年1〜2月、n=5,241）。採用できない前提で伸ばす手段として位置づけると、経営者の一番痛いところに接続する
- **締めの「止まっていたものが、動き出す」** がヒーローの「止まっている」を回収する。ここで初めてサイト全体が一本の動詞でつながる

## セクション6｜担保（定着まで、を証明する）

```
We don't hand off. We stay until it works.
導入して終わりにしない。成果が出る運用まで伴走する。

戦略レポートも、きれいな設計図も、それ自体は1円も生みません。
現場が使い始め、使い続けて、初めて数字が動きます。

だからConsilegyは、設計図を渡して終わりにしません。
ダッシュボードの読み方、営業会議での使い方、1on1での問いの立て方まで一緒に設計し、
「これがないと仕事が回らない」と現場が言う状態まで並走します。
```

### 設計意図

- `We don't hand off. We stay until it works.` は英語版サイトとバナーにあるのに、**日本語トップに存在しない**。最大の差別化を翻訳し忘れている状態
- 「伴走」は競合18社中5社が使う飽和語。だから「伴走します」で終わらせず、**何をするのかを具体で書く**（ダッシュボードの読み方／営業会議での使い方／1on1での問いの立て方）。ここまで書くと伴走が飾りでなくなる

## セクション8｜誰がやるか

```
設計するのは、代表の山口聖子です。

[顔写真]

B2Bマーケティング歴10年以上。Moloco、Kaizen Platform、アリババ、UCC上島珈琲、
西川などで、マーケティング・営業・CRMの設計と実装を担当してきました。
LinkedInで6,400名、ニュースレターで約2,000名に、日本のB2B収益設計について発信しています。

「戦略だけ描いて去る人」を何度も見てきたので、私はそうしないと決めています。
```

### 設計意図と、根拠が割れている点

- 日本のB2B購買調査で信頼度2位は「販売会社の個別説明」59.8%。**人が信頼の対象**になっている
- 会社概要は信頼判断の3大要素の一つ（サイトエンジン調査 n=218）
- LinkedIn 6,400フォロワー・ニュースレター約2,000名は、この規模の会社としては強い証拠。**現在まったく使っていない**

**重要な反証**：CXLの研究（参加者445名＝写真なし群205名＋写真あり群240名、海外）では、
デジタルマーケティング企業の創業者写真は逆効果だった。
**写真「なし」のほうが「より専門的」に見られ、「より大きな顧客を抱えている」と認識された**（8サイト中3サイトで統計的有意）。

ただしこの研究は大企業クライアント想定のデジタルマーケティング企業という限定文脈であり、
中堅B2B向け・代表個人の専門性が売りという Consilegy の状況にそのまま当てはまるとは限らない。

**結論：このセクションは必ずA/Bテストで検証する。** 根拠が両方向に割れている数少ない項目。

```
まず、どこで止まっているかを見つけましょう。

収益診断は無料です。3分で終わります。
現在のツール構成・営業プロセス・組織体制をうかがい、
収益がどこで漏れているか、何から手をつけるべきかを整理してお返しします。

診断は、質問が価値ではありません。結果が価値です。

診断結果をもとに、30分の無料相談で優先順位を一緒に整理することもできます。
```

### 設計意図

- **「30分無料相談」を診断の次に置く。** 現状は診断と相談が並列で訪問者が選べない。`診断 → 相談 → 提案` の階段にすると、最初に迫られる決断が「3分のフォームに答える」だけになる

# 4. サイト全体の設計

## サイトの役割定義

> 「うちの何が悪いのかわからない」状態で来た訪問者を、
> 「原因は構造だ」と理解した状態にして、収益診断まで運ぶ。

サービス紹介も事例もコラムも、この1本の導線に奉仕する部品として配置する。
逆に言えば、この導線に貢献しない要素はトップ階層に置かない。

## 現行サイトの構造的な問題

### 問題1：サービスの分類軸が2つ同居している（最重要）

同じ提供物が、場所によって違う切り方で説明されている。

| 場所 | 分類軸 | 中身 |
|---|---|---|
| トップページ | **時間軸** | Step 01 現状分析 → Step 02 再設計PJ → Step 03 伴走・顧問 |
| ナビ／料金 | **機能軸** | レベニューアーキテクチャ設計／マーケ戦略／CRM実装／HubSpot／定着支援 |

訪問者は「Step 02の再設計プロジェクトって、5つのサービスのどれ？　全部？」がわからない。

**時間軸（Step）を主にする。** 理由は3つ。

- 訪問者は「自分が今どの段階か」は答えられるが、「自分に必要な機能は何か」は答えられない（それがわかっていれば相談に来ない）
- 価格が時間軸で設計されているため、料金ページと自然に一致する
- 「戦略で終わらせず定着まで」という差別化そのものが時間軸の主張。分類軸を時間にすると構造がメッセージを補強する

機能別5ページは削除せず、SEOの受け皿として残す（「HubSpot 導入支援」等の検索需要は実在する）。
ただし**ナビからは外し**、サービスハブと記事からの内部リンクで到達させる。

### 問題2：Revenue CRM がナビ2番目にある

クローズドβの自社プロダクトがナビの一等地を占め、①訪問者の大半が買えない ②ベンダーフリーの主張と緊張する、という2つのコストを払っている。

→ **はしごの1段目として位置づけ直す**（本文セクション2）ことで解消する。

### 問題3：旗を立てるページが階層の奥にある

「レベニューアーキテクチャ設計とは」「RevOps再設計とは」はカテゴリを創る中核ページ。
検索・AI検索（GEO）の入口としても最も価値が高いのに、ドロップダウンの中に埋まっている。

### 問題4：CTAページが4本ある

`/diagnostic/`（無料で診断する）／`/free-consultation/`（30分無料相談）／`/download/`（資料）／`/contact/`（問い合わせ）。
訪問者が選べず、計測も割れる。**収益診断に一本化する。**

### 問題5：EN版が末端にある

外資SaaSのJapan市場参入は主要ターゲットの一つで、LinkedInでは英語投稿に反応もある。
その受け皿が言語スイッチャーとして端に置かれているのは、流入とサイトが繋がっていない状態。

## 主要ページの役割

### /services/ — サービスハブ

訪問者が「自分はどこから始めるべきか」を1ページで判断できる状態にする。

1. 3ステップの全体図を1枚で
2. 各ステップ：目的／期間／成果物／価格帯を同じフォーマットで
3. 「どこから始めるべきか」の判断ガイド
4. 個別テーマ（HubSpot導入／マーケGTM設計など）への導線
5. CTA：無料で収益診断

`/pricing/` はここに統合し301。価格を単独ページに置くと「価格だけ見て帰る」動きが生まれる。文脈の中に置く。

### /revenue-architecture/ — 旗ページ

カテゴリを創る。検索・AI検索の入口。ここだけは営業ではなく**定義と主張**を書く。

- レベニューアーキテクチャとは何か（定義）
- なぜ今それが必要なのか（部門最適の限界）
- RevOpsとの関係（`/about-revops/` を配下に統合）
- 従来のコンサル／ツール導入と何が違うか
- 日本市場特有の論点（稟議・合意形成をプロセスとして設計する）

日本語でこの語を正面から定義している会社はまだ確認できていない。**先に定義を置いた側がカテゴリを取る。**

### /case-studies/ — 導入事例

症状 → 打ち手 → 結果の3段で統一し、**症状の書き出しをトップの症状リストと同じ言葉にする**。
訪問者がトップで自己認識した症状と事例の見出しが同じ語彙だと、事例が「自分の未来」として読める。

### /crm/ — Revenue CRM

冒頭に位置づけの一文を置く。クローズドβであることを弱みとして隠さず、
「一緒に作るパートナーを探している」と書くほうがこの段階では強い。

### /company/ — 会社概要

中堅B2Bでは「誰がやるのか」が発注判断そのもの。代表の経歴を独立ブロックで。
支援40社・LinkedInフォロワー6,400名・ニュースレター約2,000名はいずれも強い信用材料。

## 計測設計

CTA一本化は見た目の問題ではなく**計測の問題**として効く。
現行は診断・相談・資料DL・問い合わせの4本に割れているため、どのページが売上に効いているかが測れない。

1. 主コンバージョン＝収益診断フォーム送信、1つだけ
2. 副コンバージョン＝資料DL、ニュースレター登録
3. 診断フォームで取得している**業種6分類（SaaS・IT／製造／商社・卸／専門サービス／小売・EC／その他）を必須項目に**
4. 診断リードは業種でTier判定（SaaS・IT と 小売・EC が Tier 1）してから温度づけ
5. どのページを経由した診断がTier 1比率が高いか、を月次で見る

4と5がつながると「どのコンテンツがICPを連れてくるか」がわかる。
これは**Consilegyが顧客に売っている設計を自社で回している状態**でもあり、事例として語れるようになる。

## 収益診断の設計（ベンチマークから）

国内の診断オファー14件・海外8件を調べた結果の推奨。

| 項目 | 推奨 | 根拠 |
|---|---|---|
| 名称 | 「収益診断」でよい（「[対象領域]＋診断」が国内の支配的パターン。14件中12件） | 国内実例の型 |
| 所要時間 | 「3分」を名称の近くに明示 | 「1分」「3〜5分」「120秒」明示が主流 |
| 設問数 | 10問前後 | STRADDLE 10問、Prometheus 10問、HelloGrowthCRM 8問 |
| 1問目 | 業種選択（6分類） | 業種別ベンチマーク比較を成立させる必須要素 |
| 結果 | 即時スコア表示＋4〜5ドメイン別のレーダーチャート | 即時自動判定が多数派 |
| 差別化 | **業種別ベンチマークとの比較** | 実例では少数派＝差別化になる |
| 導線 | 診断直後に「30分無料相談」の予約ボタン | 海外RevOps系実例の主流 |
