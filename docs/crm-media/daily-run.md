# Revenue CRMの記事を毎朝公開する手順

## 目的と優先順位

法人営業1本、スクール1本を、それぞれ日本語・英語のセットで公開する。現在使える機能を読者の困りごとにつなげる。一般論だけの記事は出さない。本文の型・frontmatter・文体はREADMEと既刊に従う。本人の声の基準は `~/Claude/_config/roles/seiko.md` を最初に読む。

## 毎回の実行

1. 開始と実行環境を報告。CRMとサイトの最新mainを確認する。他の未コミット作業は変更・一括追加しない。作業中のブランチを製品の最新コードと取り違えない。古いクラウド専用ツールやMacのマウントパスを必須にしない。
2. サイトの `src/data/crm-updates.ts` を読み、対象エディション・根拠PR・既刊を照合する。次に最新CRMの画面・ヘルプ・docsを探す。新しいコード変更が無くても、既存機能の未紹介の使い方を探す。パスが無ければ実在するツリーから検索する。
3. 各segmentで、困りごと、使う機能、具体的操作、根拠ファイル、既刊との違いを記録して選ぶ。過去の保留は現在のコードで再検証。記事の核心に無関係な周辺機能の不足で丸ごと保留にしない。
4. 日英の原稿を作る。場面→損失→具体的な画面と操作→最初の一歩→本文末CTAを1回。日本語1,200〜1,800字が目安。数字・体験・出典を捏造しない。匿名化し、導入社数・実顧客名・「AI搭載」・「ノマド」・エムダッシュは使わない。英語は読者向けに書き直す。
5. 記事に合う実画面を既存画像かデモで確認する。デモは閲覧と撮影だけ。メール登録・送信・同期・設定変更をしない。認証済みデモのURLを使い、/demosにメールを送信しない。ブラウザが使えなければREADMEの画像なし公開の例外と理由を記録する。PCのタブや個人情報を画像に含めない。
6. Recraftの指定プロジェクトでログイン済みなら場面の写真を生成する。人物はJapanese、明るい室内、読める文字やロゴなし。2026-11-10のユーザー指定に従い、表紙は文字を重ねない場面写真を使う。Recraftが未ログイン・プロジェクトの権限不足・生成不可ならimagegenで生成。既存の写真と並べ、暖かい色味、柔らかい自然光、余白のある少し引いた構図を確認する。写真生成がすべて使えない場合のみ、既存スクリプト `node scripts/generate-eyecatches.mjs <slug>` で文字SVGを生成し、理由を報告する。生成方法とプロンプトを記録。
7. 執筆に関与していない別エージェントに日英4本と一次情報を渡し、事実・読者・重複・禁止事項・画像との整合をレビューさせる。直し、重大な未解決がある記事は公開しない。
8. `npm ci` と `npm run build`。4つのdist記事HTML、画像、CTA、日付、日英URLを確認する。変更ファイルだけを明示して1コミットにまとめる。最新mainとの差分を確認してから `git push origin HEAD:main`。CRMへのpushはしない。
9. 5分を上限に4記事のHTTP 200と記事タイトルを確認する。push成功と公開成功を混同しない。サイトの配信が失敗したら原因を調べ、自分の変更が原因なら直す。
10. 結果は1通。公開URL、画像の状態、レビュー修正、公開できなかった理由を短く報告。開始・トピック決定・執筆・レビュー・ビルド・push・公開確認の節目にも進捗を出す。

毎日新しい記事を保証するために機能や効果を作らない。出せない場合は調べた候補と成立しなかった具体的理由を残す。「候補が尽きた」とだけ報告しない。
