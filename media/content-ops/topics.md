# 調査で判明した3つの事実（戦略が変わります）

## 事実1: 「レベニューアーキテクチャ」は日本語圏の完全な空白地帯です

カタカナ表記「レベニューアーキテクチャ」で検索した結果、返ってくるのはレベニューマネジメント（航空・ホテルの価格最適化）、レベニューシェア型契約、グリーンレベニューアーキテクト（GX人材）といった**無関係な語ばかり**でした。検索エンジンがこの語に対する適切な候補を持っていない、典型的な状態です。

さらに重要なのは次の点です。

- Winning by Design の Bowtie を、**CR1〜CR8 / Δt1〜Δt9 の指標体系まで含めて解説した日本語記事はゼロ**
- SPICED だけが部分的に輸入されている（Magic Moment などが解説）が、**Revenue Architecture という上位概念に接続されていない**
- Jacco van der Kooij の書籍『Revenue Architecture』（2023年10月刊、556ページ）に**日本語版は存在しない**
- 日本語圏の議論は「The Modelの限界 → じゃあどうする？」で止まっており、受け皿として RevOps（組織論）が語られているが、**測定可能なデータモデルが提示されていない**

つまり、**「The Modelの限界」という問いに対する定量的な回答が、日本語で存在しません。** Bowtie の CR/Δt 体系はまさにその回答になります。ここに正典を置けば、構造的な空白を埋める唯一の記事になります。

なお、**Consilegy の英語ページ（consilegy.com/en/）が既に "Japan GTM and Revenue Architecture" でインデックスされています。** 日本語側を押さえれば両言語で取れます。

## 事実2: この領域の数字は壊れています。それ自体が記事になります

調査の過程で、日本語圏のB2B・RevOps記事が**検証不能な数字を相互引用して権威を水増ししている**構造が見えました。

- **「B2B購買の意思決定関与者は平均5.4人」** → 米CEB社が米国企業を対象にした2015年の調査。日本のデータではありません
- **「Gartner: 2026年までに高成長企業の75%がRevOpsを導入、現在は30%未満」** → Gartner原文は「2025年までに75%」（2021年5月発表）のみ。「2026年」も「30%」も**原文に存在しない改変**
- **「BCG: RevOps成熟企業は成長19%速く、株価71%高い」** → BCG / Forrester / SiriusDecisions に帰属が矛盾。BCG帰属は誤りの疑い
- **「MA導入企業の90%は失敗する」** → 2020年の対談における発言。統計調査ではありません
- **「勝率19%（前年29%から低下）」** → 元レポートに「全て相対値」と明記されており、誤読

**「出典を全部辿ってみた」という記事は、それ自体が一次情報です。** 誰もやっていないので引用されます。正典に1本追加することを強く勧めます。

## 事実3: 日本のベンチマークが存在しない領域が特定できました

調査の結果、次の10領域について**日本の公開一次データが存在しない**ことが確認できました。

日本のDMU人数 / 稟議で否決された理由の構成比 / CRMの重複データ率 / CRM失敗要因の独立系ランキング / **日本のリード→商談化率・受注率** / CAC回収期間 / MA解約率 / 日米のCS期待値比較 / 海外SaaSの日本参入成功率 / オンボーディング完了率と継続率の相関

**このうち1つでも自分で測れば、その領域で唯一の一次データを持つ立場になります。** 年次調査は「稟議で止まる理由」と「日本の転換率ベンチマーク」の2つに絞るのが最も効率的です。

# 実務ノートへのデータの扱い方（方針変更のご相談）

ご指示は「各記事ちゃんと市場調査してデータを入れる」でした。正典10本については、下記の通り全面的にデータで固めました。

一方で**実務ノート80本に外部データを入れるのは、逆効果になると考えています。** 理由は2つです。

第一に、実務ノートの価値は一次情報そのものです。他社の調査データを引用し始めると、AIでも書ける記事に近づきます。第二に、日次で書く記事に毎回出典調査を挟むと、1本45分の設計が崩れます。

そこで実務ノートには、外部データの代わりに **「この記事で出すべき自社の数字」** を1本ずつ指定しました。これがそのまま一次データの在庫になり、年次調査の設問候補にもなります。80本書き終える頃には、**他の誰も持っていない数字が80個溜まっている**という設計です。

外部データが本当に効く実務ノートには、個別にデータを紐付けています。

## ⑥ The Model と Revenue Architecture はどう使い分けるか

- **URL**: `/architecture/the-model-vs-revenue-architecture/`
- **狙う問い**: 「The Model 限界」「The Model 分業 問題」
- **競合状況**: 「The Modelの限界」記事は**既に飽和**（パーソル総研、リブ・コンサルティング、カノープス等）。ただし**限界の先の定量的な答えを出している記事はゼロ**。差別化はそこ
- **主張**: The Model は獲得の分業と予測に強く、継続収益の設計には向かない。両方を捨てず、担当領域を分ける

**使うデータ**

| データ | 出典 |
|---|---|
| 『THE MODEL』2019年1月刊、**10万部突破** | 翔泳社プレスリリース |
| **著者・福田康隆氏本人の但し書き**: 「自社の状況に合致するか確認せずに鵜呑みで導入する企業への警鐘」として執筆。The Modelは顧客セグメント・チャネル・組織成長ステージで変わるため「機能する／しない」を論じること自体が無意味 | SalesZine インタビュー |
| **CR1〜CR8**: 従来のMQL→SQLはCR1×CR2、Opportunity to CloseはCR3×CR4に分解される | WbD Bowtie Standard v1.0 |
| NRR 100%未満のグループは母集団の成長率中央値（24%）を下回る | SaaS Capital 2025 ※帯別の具体値は使わない |
| 国内B2B SaaSの**約38.4%がNRR 100%未満** | Fullstar 2025、n=200 ※ベンダー調査 |
| **RevOps認知度は全体で1割程度** | バーチャレクス 2023、n=9,798 |

**この記事の最大の武器は、福田氏本人の但し書きです。** 「The Modelは古い」と外から言うのではなく、**著者本人が最初から警鐘を鳴らしていた**という事実から入ると、品を保ったまま強い主張ができます。その上で、The Modelの指標がBowtieのCR体系にどう分解されるかを示せば、対立ではなく包含の関係として提示できます。

## ⑧ CRMのデータが汚れる構造と、設計で防ぐ方法

- **狙う問い**: 「CRM データ 汚い」「SFA 入力されない」
