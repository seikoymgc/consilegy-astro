# Codexで執筆し、Claudeで品質審査する

## 2026-11-20：公開済み記事の全件監査を優先

本人の全件チェック指示に従い、[全件監査・修正・再審査](./all-published-audit.md)を新規記事より優先する。初回の対象台帳は485ページ。審査・修正・本番反映を別々に記録し、全件を完了するまで終わったと報告しない。Claudeの指摘を保存するだけで止めず、通常修正と再審査を続ける。


## 2026-11-20：Claudeの指摘後は修正・再審査まで進める

本人指示「こうした場合に、修正して更新してほしいんだけど」により、記事の品質指摘への通常の修正をあらかじめ承認された作業として扱う。指摘だけを保存して終了しない。Codexが出典と原稿を照合し、誤りの訂正、根拠の弱い主張の限定・削除、構成・自然な表現・重複の改善を行い、更新した原稿をClaudeで再審査する。AIの指摘自体も事実とは限らないので、出典を確認して採否と理由を記録する。

Critical・Majorが残る間は修正できる箇所を直して再審査を続ける。未確認の資料は追加調査・別の一次資料・削除・限定で解決し、同じ未確認理由だけを繰り返さない。合格のために基準を緩めたり、指摘の重大度を恣意的に下げたりしない。原稿と根拠の版ごとに審査結果と対応メモを残す。

本人に未確認の新しい見解、体験、実績、独自の製品推奨を加えないと直せない場合だけ、その具体的な一点を本人へ確認する。既存の主張を保つ通常の修正のために、毎回承認を求めない。人による独立レビュー、本人の公開表示での全文最終OK、画像・ビルド等の公開条件を実施済みと偽らない。画像や公開表示が未作成という指摘は公開準備の別工程へ進め、本文を無限に書き直す理由にしない。


日次タスクは、このフォルダの統合チェックリストを読んでから執筆する。執筆後に以下を実行する。CLIの既存ログインを使う。Claude Codeのログインとネットワーク接続が必要。審査不能を合格扱いしない。

```sh
python3 scripts/claude-article-review.py path/to/article.md \
  --evidence path/to/plan-and-author-sources.md \
  --evidence path/to/fact-check.md \
  --output media/content-ops/reviews/YYYY-MM-DD-slug-claude-v1
```

`--evidence` は繰り返せる。本人の原文・確定状況、企画記録、一次資料のURL、公開レビューの確認記録、許可済み修正範囲など、実際に存在する根拠だけを渡す。顧客の機密・個人情報は除いた記事用の資料にする。未確認の主張を本人の考えとしない。

独立作業コピーにスクリプトがない場合は、元の共有フォルダ `/Users/seikoyamaguchi/Claude/consilegy-astro/scripts/claude-article-review.py` を絶対パスで実行し、原稿と根拠にも作業コピー内の絶対パスを渡す。スクリプトは元フォルダの統合チェックリストを基準にする。

3工程は別々のClaude呼び出しとし、事実検証（F/P）、編集レビュー（S/C/R）、校正・推敲（J/P）を行う。原稿・根拠と基準の版（SHA256）、実行日時、ClaudeのセッションID、応答を残す。本人の審査とは呼ばない。構造化応答を検査し、チェック項目の欠落、原稿にない引用、CLIエラー、タイムアウトは未完了にする。

Claudeはレビューだけを行う。ファイル書き込み、シェル、git、MCPは利用させず、ローカル設定と自動push等のフックを読み込まないモードで起動する。WebSearch/WebFetchで一次情報を読む。取得できない資料・提供されていない画像・本人の確認は「要確認」。本文の機械的な検査だけで事実検証したとは扱わない。

結果は出力ディレクトリの `report.md` と `report.json`。初回は元原稿を変更しない。Critical・Majorと要確認が残る場合は終了コード2。全項目の実施結果、原文の引用、理由、修正案、根拠、対応状況を確認し、承認済みの範囲でだけ修正する。本人の既存の主張や文体を別のものへ変える修正や、新しい実体験・成果の追加が必要な場合は、具体的な確認事項を本人に示す。通常の訂正と推敲は冒頭の2026-11-20の承認範囲で進める。

通信・形式の障害から、同じ原稿・根拠・基準・指示の保存済み応答を使って再開する場合に限り `--resume` を使える。原稿を修正した場合は使わない。

修正後は同じ出力先を上書きせず `v2` などで再実行する。前回の指摘に対して、修正した箇所・理由・承認範囲を対応メモへ残し、それも `--evidence` で渡す。古い原稿の合格を使い回さない。

```sh
python3 scripts/claude-article-review.py --check path/to/review/report.json
```

このコマンドが終了コード0でも、人による独立レビュー・本人が公開の形の全文を読んだ最終OK、画像・表示・リンク・schema・本体とmediaのビルド・公開後確認は別途必要。AI審査の合格は公開承認ではない。本文・基準・根拠が変わると再審査が必要。
